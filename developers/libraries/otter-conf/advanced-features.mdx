## Nested fields

The parser recursively flattens public nested struct fields. A section `clock` containing `time_format` becomes `clock_time_format`. Define defaults at every level.

## Custom values

A custom value type provides public `parse(s: str)` returning an error union and `to_str(self)` returning a NUL-padded fixed byte array. `otter_geo.color.Color` implements this contract.

Set `strict_custom_values` when an invalid custom value must fail instead of keeping the default.

## Indexed entries

Import `otter_conf.dynamic`. `Dynamic(Elem, prefix)` represents indexed entries such as `button_0_name` and `button_0_command`.

- `init(alloc)` creates its owned list.
- `len()` and `slice()` expose entries.
- `deinit()` releases entries and their owned fields.
- Indices are bounded to `0..4095` by `support.max_dynamic_entries`.

Elements containing owned text need their own consuming `deinit`, like top-level configs.

## Imports

Import resolution is opt-in through `loader.load_with_imports` or `otter_conf.imports`. A plain `load` does not resolve imported files.

`imports.resolve` returns merged content and owned paths. `resolve_with_limit` applies a merged-output size bound. Nesting is capped at 128 levels.

Watch all returned paths, not only the root file. Keep import path ownership separate from the config when moving values out of a load result.

## Schema-free reads

`parser.entries(alloc, content)` returns typed key/value records for readers without a schema. This differs from parsing a config: your caller decides how to interpret and retain each entry.
