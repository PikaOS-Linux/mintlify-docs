`otter-vte` is the reusable terminal rendering boundary. It depends on geometry and rendering, not a terminal application's UI. Import `otter_vte.command_list`, `ops`, `cell_glyphs`, `cell_renderer`, `renderer`, or `snapshot`.

The cell renderer accepts explicit cell/selection/host interfaces and a borrowed draw context. It does not reach through arbitrary application pointers.

`DynamicCommandList` and `Renderer` are owned resources initialized with an allocator. Image-free terminal raster paths use `renderer.no_images`.

## Lua

`otter_vte_lua` exposes `otter.vte`: glyph rectangles, powerline classification, batching checks, and bounded plugin-owned pixel canvases. These operations stay inside the process, so they require no capability. They do not create a terminal session or PTY.
