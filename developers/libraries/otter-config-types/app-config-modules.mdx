## Shared application schemas

Each module below is imported as `otter_config_types.<name>` and exposes `Config` plus its supporting types.

| Group                      | Modules                                                                |
| -------------------------- | ---------------------------------------------------------------------- |
| Panels and navigation      | `bar`, `launcher`, `dock`, `taskbar`, `overview`                       |
| Session and authentication | `greeter`, `lock`, `polkit`, `idle`, `logout`                          |
| Feedback and display       | `notifications`, `osd`, `wallpaper`, `nightlight`, `theme_gen`         |
| Applications and services  | `term`, `jade`, `transcribe`, `assist`, `monitor`, `search`, `clicker` |

Struct nesting and field names define the flat config keys. Read the schema rather than deriving a key from a UI label.

## Small tools

Additional small-tool schemas live in `otter_tools_core.app_configs`, including `Calc`, `Emoji`, `Picker`, `Timer`, `Weather`, `Note`, `Calendar`, `Clip`, `Recorder`, and `Vox`. They are not modules in `otter_config_types`.

## File names

Do not assume every file is `otter-<app>.conf`. The Lua schema `file(app)` reports the app's actual file name. Greeter uses `/etc/otter-shell/otter-greeter.conf`; user application paths resolve through XDG helpers.

`defaults` and `parse` Lua tables retain nested sections and use arrays for Dynamic entries. Enum values become tag strings and colors become `#RRGGBBAA` strings.
