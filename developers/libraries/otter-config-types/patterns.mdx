## Define fields once

Keep the schema's fields public and defaulted. Applications parse these structs; editors inspect the same types. Configuration key names are part of the user-facing format, so do not rename fields only to match a code-style preference.

## Owned values

Use `text.Text.of("...")` for string defaults and `text.TextList` for string lists. A struct owning `Text`, `TextList`, or `Dynamic` entries declares `deinit(self)` and delegates to `otter_conf.support.free_config`.

This applies to nested sub-configs a widget owns independently. A copy of resource-shaped config data is not an independent owner; clone text where both values must live.

`bar.CustomButtonConfig.to_button_config(&self, alloc)` clones strings into the returned button config so it can outlive the parsed source.

## Editor metadata

Import `otter_config_types.fields`:

| Function                       | Result                                     |
| ------------------------------ | ------------------------------------------ |
| `is_known_field(T, key)`       | Whether the flat key belongs to the schema |
| `field_needs_quoting(T, key)`  | Quoting rule, or null for an unknown key   |
| `get_enum_field_names(T, key)` | Static enum names, or null                 |

Metadata understands flattened sections and Dynamic indexed keys. Unset optional fields can be absent from serialized defaults while still existing in the schema.

## Adding settings

Update the shared schema and app behavior together. Expose new configurable behavior in Settings where relevant, including controls required to maintain it. Verify parsing, serialized defaults, and field metadata rather than testing only the application's local struct.
