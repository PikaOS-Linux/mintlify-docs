Native bar widgets live in `otter_ui.widgets.*`; Surface Description emitters live in `otter_ui.widgets.specs.*`.

## Ownership

Widgets embed a `Widget` shell for geometry and pointer state. They do not store font or shared-service pointers.

- Width measurement takes a borrowed mutable font.
- `draw_frame` uses resources lent through the current frame.
- `sync_state(service)` updates from an app-owned client.
- Input methods take a service per call or return an action the app applies.
- Widgets that own a private client expose descriptor/process entry points.

The owner drives synchronization when service descriptors become ready and requests redraw from returned change flags. The otr API does not use subscriber callback/context registration.

## Registries and time

`widget_registry` uses `Slot` indices. A scoped `widget_by_name` lookup does not transfer ownership. App-owned `widgets.clock.LocalClock` keeps timezone state; pointer/tooltip operations receive time explicitly.

## PipeWire volume

The ordinary volume widget is service-independent. Add `otter_ui_volume` and use its `volume` module to apply sync, scroll, click, and popup actions to a borrowed PipeWire client. This keeps PipeWire out of UI-only apps.

## Lua

`otter.ui.widgets` exposes native widget formatting/layout rules and `draw(name, x, y, height, view, width?)`. It does not independently create UPower, NetworkManager, or PipeWire clients. Supply view data from host-registered desktop bindings.

`otter.ui.art` provides asynchronous MPRIS album-art fetching under the `media` capability. Hosts must register it explicitly. Built-in widget drawing and stateful service access are separate surfaces.
