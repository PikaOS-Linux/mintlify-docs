Layout types are in `otter_ui.ui_frame_spec`. Every `Node` has a `layout` field of type `LayoutSpec`.

## Rows and columns

```otr
fn toolbar(title: str) void {
    var actions = [2]Node{
        Node.button(Id.named_comptime("toolbar.cancel"), "Cancel"),
        Node.button(Id.named_comptime("toolbar.apply"), "Apply"),
    }
    var cells = [2]Node{
        with_layout(Node.label(Id.named_comptime("toolbar.title"), title, 14, null), .{ width: .fill, height: .fill, align_y: .center }),
        Node.row(Id.named_comptime("toolbar.actions"), .{ width: .fit, height: .fill, gap: 8 }, &mut actions),
    }
    root := Node.row(Id.named_comptime("toolbar"), .{ width: .fill, height: .fixed{ 40 }, padding: geo.Padding.uniform(4), gap: 12 }, &mut cells)
    _ = root
}

fn with_layout(n: Node, l: ui_frame_spec.LayoutSpec) Node {
    var out = n
    out.layout = l
    return out
}
```

`Node.row` and `Node.column` take an id, a `LayoutSpec` and a mutable slice of children. A row places children left to right, and a column top to bottom. The constructors for leaf nodes use a default layout. Assign `layout` afterwards to change it, as `with_layout` does here.

## Sizing

| `SizeRule` | Meaning |
| --- | --- |
| `.fit` | The measured size of the content. This is the default. |
| `.fill` | The space the parent has left. |
| `.fixed{ n }` | Exactly `n` logical pixels. |

`LayoutSpec.fixed(width, height)` builds a spec with both axes fixed.

| Field | Meaning |
| --- | --- |
| `width`, `height` | A `SizeRule` per axis. |
| `min_width`, `min_height`, `max_width`, `max_height` | Limits applied after the rule. |
| `padding` | Space inside the node, around its children. |
| `gap` | Space between neighboring children. |
| `flex` | The share of leftover space a `.fill` child takes, relative to its `.fill` siblings. Defaults to 1. |
| `align_x`, `align_y` | `start`, `center`, `end` or `stretch`. |
| `clip` | Clips children to the node's rectangle. |
| `shrink` | When fitted children overflow a row or column, shrinks them in proportion. A button then cuts its text with an ellipsis. |

## Other containers

A node's `kind` selects how it arranges children.

| Kind | Arrangement |
| --- | --- |
| `row`, `column` | In a line, with `gap` between children. |
| `stack` | On top of each other. Use it to put content over a panel. |
| `grid` | In `grid_columns` columns. |
| `spacer` | Empty space that takes part in layout. |
| `scroll_view` | A column that scrolls when its children are taller than it. Build it with `Node.scroll_view`. |

For a kind with no constructor, write the node literal:

```otr
var layers = [2]Node{
    Node.panel(ids.surface, .{ width: .fill, height: .fill }, panel_spec),
    .{ id: ids.column, kind: .column, layout: .{ width: .fill, height: .fill, padding: geo.Padding.uniform(16), gap: 6, clip: true }, children: &mut content },
}
root := Node{ id: ids.card, kind: .stack, layout: .{ width: .fixed{ 640 }, height: .fixed{ 420 } }, children: &mut layers }
```

## Trees are borrowed

`Node` is a `ref struct`. It borrows its children slice and its text, so a tree lives on the stack of the function that renders it. Build the tree, pass it to `frame.render`, and let it go.

Ids are separate from that storage. An id names the same control in every frame, wherever its node happens to sit.

## Long lists

A list of thousands of rows should build nodes only for the rows on screen. `otter_ui.ui_frame_list.UniformList` does the arithmetic for rows of one height.

```otr
fn visible_rows(scroll_offset: usize, selected: usize) void {
    list := ui_frame_list.UniformList{ item_count: 10000, item_height: 28, viewport_height: 280, scroll_offset: scroll_offset }
    range := list.visible_range()
    for i in range.start..range.end {
        y := range.y_offset + @int_cast(i32, (i - range.start) * 28)
        std.io.printf("row {} at y {}\n", .{ i, y })
    }
    next := list.move_selection(selected, .page_next)
    std.io.printf("{} {}\n", .{ next, list.scroll_offset_for_selection(next) })
    if list.hit_index(geo.Rect{ x: 0, y: 0, width: 300, height: 280 }, geo.Point{ x: 20, y: 100 }) |index| {
        std.io.printf("pointer over row {}\n", .{ index })
    }
}
```

`visible_range()` gives the first and last row to build and the y offset of the first. `hit_index` maps a pointer position to a row, `move_selection` applies a keyboard move, and `scroll_offset_for_selection` returns the scroll offset that keeps a row in view. `UniformGrid` does the same for a grid of equal cells.

Rows of mixed height use `otter_ui.scroll.SnapRows`.

## Lua

`otter.ui` has the same list and grid math for Lua frames.

```lua
local ui = require("otter.ui")

local first, last, y = ui.list_range(#items, 28, view_height, scroll)
for i = first, last do
  draw_row(items[i], y)
  y = y + 28
end
```

`list_hit` and `list_move` match `hit_index` and `move_selection`. `grid_range` is the grid form. In the `sd` table, `sd.row(x, y, gap)` and `sd.col(x, y, gap)` open containers, and `sd.finish()` closes the innermost one.
