## Dispatch

`UiState.hit_test(point)` returns an optional hit region. `dispatch(event)` updates input state and returns `DispatchResult` for the app to interpret. Dispatch events and results are value types in `ui_frame_types`.

Use the same stable `Id` in rendering and input handling. A click target needs a hit region; a visible rectangle alone is not an action.

Text editing has separate `input_buffer`, `text_edit`, and `text_box` modules. Feed committed text and composition events correctly rather than interpreting IME preedit as final text.

## Overlays

`UiFrame.queue_overlay` lays out its borrowed node immediately into an overlay command segment. `finish()` places that segment after main content. It does not store a raw node pointer until the end of the frame.

Queue an overlay after its anchor has been rendered. `OverlayAnchor`, `OverlayPlacement`, and `place_overlay` define placement against the viewport. Tooltip text is copied into the per-frame label arena.

`should_dismiss_overlays(point)` helps determine click-off dismissal. Overlay damage records support redraws when popups move or disappear.

## Virtualized input

`UniformList` exposes `visible_range`, `hit_index`, `move_selection`, and `scroll_offset_for_selection`. `UniformGrid` provides the corresponding row-aware operations. These helpers do not require a node per off-screen item.

## Lua boundary

`otter.ui` offers ID and list/grid geometry helpers. Lua widgets emit SD commands and hit records; the plugin host delivers `event(kind, id, x, y)` to the plugin export. The native `UiState.dispatch` object is not exposed as a Lua constructor.
