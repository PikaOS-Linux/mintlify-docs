## Font ownership

Import `otter_render.font`. `Font.init(alloc, io, options)` returns an owned `Font`, not a heap pointer. Its consuming `deinit()` closes backend resources.

`InitOptions` borrows paths or bytes during initialization. Explicit static font data can remain embedded and be read in place. File-backed font operations take `std.Io` explicitly.

`measure_text_at_scale(text, size, factor)` uses an explicit `Scale`. Terminal layout uses `terminal_metrics_at_scale`.

## Shaping

Import `otter_render.text`. `TextSystem.init(alloc, &mut font)` creates the shaping system. Its methods also take the mutable font explicitly; the system does not store a font pointer.

Keep a `ShapeScratch.init(alloc)` resource beside the system. Shaped runs and line views borrow scratch storage. Consume or copy them before reshaping with the same scratch.

- `measure` keeps a simple-text fast path.
- `shape_into`, `draw`, and clipped variants handle shaped glyph runs.
- `wrap`, `truncate`, and `cursor_rect` support controls and editors.
- A different font instance returns `TextError.FontMismatch` on shaping paths.

HarfBuzz performs shaping. `otter_render.bidi` provides native UAX #9 layout using Unicode 17 tables. Do not configure the obsolete itijah backend.

## Cache-safe drawing

Cached glyph references borrow the font. Use combined `draw_glyph_index`, `draw_char`, and `draw_emoji_glyph` helpers when loading and drawing together would otherwise overlap mutable font borrows.

## Lua

`require("otter.render").measure(text, size, scale)` returns logical width. It accepts at most 16 KiB of text per call. The host must register `otter_render_lua.render.module()` before a plugin can require it.
