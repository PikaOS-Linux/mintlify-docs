## Colors

`otter_render.color` re-exports `otter_geo.color`. Prefer the geometry package when you only need colors. `Color.from_rgba` takes `0xRRGGBBAA`; pixel storage defaults to ARGB8888.

## Owned surfaces

Import `otter_render.surface`. `Surface` owns either a `List(Color)` or a `linux.Mapping` plus pixel offset.

| Entry point    | Ownership                                    |
| -------------- | -------------------------------------------- |
| `init_owned`   | Allocate pixels                              |
| `from_owned`   | Move an existing pixel list into the surface |
| `from_mapping` | Move a mapping into the surface              |
| `into_pixels`  | Move pixel ownership back out                |
| `deinit`       | Consume the surface and release storage      |

Use `pixels()` and `pixels_mut()` for scoped access. A surface is not a borrowed view you can retain after its owner disappears. Examples using `fromPixels` and `subSurface` do not apply to this API.

Physical drawing helpers include `fill_rect`, `fill_rect_composite`, and `draw_rect_outline`. Logical-coordinate variants have `_logical` suffixes. `logical_bounds`, `logical_width`, `logical_height`, and coordinate conversion helpers distinguish the two spaces.

## Exact scale

Import `otter_render.scale`. `Scale.one`, `Scale.from_int`, `Scale.from_q8`, and `Scale.from_q120` construct explicit scale values. Use `set_scale` instead of assigning internal scale fields.

`integer_ceil()` is not the inverse of exact logical-size conversion. A 150% output may have integer ceiling 2; preserve its exact Q8 factor for sizing and rendering.
