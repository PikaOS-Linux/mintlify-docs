## Images

Import `otter_render.image`. `Image` owns RGBA bytes and has consuming `deinit()`. File loaders take allocator and explicit `std.Io`; memory loaders consume encoded bytes only for the call.

| API family                                                   | Use                                               |
| ------------------------------------------------------------ | ------------------------------------------------- |
| `load_from_file`, `load_from_memory`                         | Decode at source size                             |
| `load_from_file_at_size`, `load_from_memory_at_size`         | Decode and fit target dimensions                  |
| `load_from_file_downsampled`, `load_from_memory_downsampled` | Reduce large source images                        |
| `load_from_file_sampled`, `load_from_memory_sampled`         | Bounded statistical sampling for color extraction |
| Foreground-aware SVG loaders                                 | Resolve symbolic `currentColor`                   |

Supported formats are PNG, JPEG, SVG, ICO, BMP, and WebP. Support does not extend to every zigimg format.

JPEG and WebP runtime decoders load lazily. Missing decoder libraries fail that format; PNG/BMP/ICO remain available. Statistical JPEG sampling uses its own native decoder. Build options can disable text, SVG, JPEG, or WebP support.

## Stores and handles

`ImageStore` owns images in generational slots. `insert` returns `ImageHandle`; `remove` transfers the image out. `image` and `image_mut` lend scoped access. Commands and UI specs keep handles, not image addresses.

## Sprites and animation

`otter_render.sprite` provides `SpriteSheet.frame_rect` and `SpriteAnim.frame_at`.

`otter_render.animation.Animation` provides integer `tick`, `lerp`, and `lerp_i32`. Custom curves live in a caller-owned `CurveTable`, not mutable module globals. `AnimBatch` borrows column slices, and `tick_batch` updates them using that table and a supplied timestamp.

Lua `otter.render.image_size(bytes)` returns dimensions and format from encoded headers. Pixel drawing uses SD/UI bindings.
