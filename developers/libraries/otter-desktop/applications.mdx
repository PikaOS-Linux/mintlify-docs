Import modules from `otter_desktop.apps`.

| Module | Purpose |
| --- | --- |
| `desktop_entry` | Parses one `.desktop` file into a `DesktopEntry`. |
| `app_list`, `watcher` | Scans the application directories, searches the entries and watches for changes. |
| `launcher`, `file_args` | Expands the `Exec` line and starts an entry. |
| `mime_catalog`, `xdg_mime`, `xdg_open` | MIME types and default handlers. |
| `icon_theme` | Detects the configured icon theme. |
| `session_catalog`, `session_launcher` | Login sessions. See [Greeter and auth](/developers/libraries/otter-desktop/greeter-and-auth). |

## List, search and launch

```otr
import std
import std.mem
import otter_utils.process
import otter_desktop.apps.app_list
import otter_desktop.apps.launcher

pub fn main(env: std.Env) !void {
    var apps = app_list.AppList.init(mem.heap)
    defer apps.deinit()
    try apps.scan(env)

    var hits: [8]u32 = unsafe { undefined }
    n := apps.search("term", &mut hits)
    for i in 0..n {
        entry := &apps.entries_view()[hits[i]]
        std.io.printf("{}  {}  {}\n", .{ entry.id(), entry.name(), entry.icon() orelse "" })
    }

    var reaper = try process.Reaper.init()
    defer reaper.deinit()
    if apps.find_by_id("otter-term") |entry| {
        try launcher.launch(&mut reaper, env, entry)
    }
}
```

`AppList.scan(env)` reads every application directory from the XDG environment. `scan_dirs` takes an explicit directory list, which is how tests use fixtures.

`search(query, results)` writes matching entry indices into your buffer and returns how many it wrote. `find_by_id` looks an entry up by desktop id. `find_by_id_or_unique_alias` also accepts a short name such as `editor` for `org.editor`, when only one entry matches it.

### Entries

A `DesktopEntry` owns its text. Read it through `id()`, `name()`, `comment()`, `exec()`, `icon()` and `path()`. `categories()` and `keywords()` return iterators, and `actions_view()` lists the entry's desktop actions. `is_visible()` is false for an entry with `Hidden` or `NoDisplay` set. Use `clone(alloc)` to keep an entry after the list changes.

### Watching for changes

`AppList.init_with_watcher(alloc)` adds an inotify watcher. Add `watcher_fd()` to your event loop and call `process_watcher_events()` when it is readable. It returns true when the list changed, and `generation()` changes with it.

### Launching

Launch functions take a `process.Reaper` from `otter_utils.process`, which collects the child when it exits. Keep one reaper for the life of your app, add its `poll_fd()` to your loop and call `drain` when it is readable.

`launch_with` takes `LaunchOptions`:

| Field | Meaning |
| --- | --- |
| `exec_override` | A command line to run instead of the entry's `Exec`. |
| `extra_env` | Extra `NAME=value` strings for the child. |
| `apply_preferred_gpu` | Honors the entry's discrete GPU preference. Defaults to `true`. |
| `terminal` | The terminal to wrap a `Terminal=true` entry in. `detect_terminal(env)` picks one. |
| `file_args_uri_list` | A `text/uri-list` to pass as the entry's file arguments. |

## Open a file or URI

`xdg_open.launch_default(&mut reaper, env, uri, token)` opens a URI with its default application. `content_type_for_uri` returns the MIME type, and `list_for_uri` returns the applications that can open it, default first.

## Icons

Icon lookup is in otter-utils, so that libraries below otter-desktop can use it. `otter_utils.icon_lookup.IconResolver` resolves an icon name or app id to a file path and caches the answer.

```otr
import otter_utils.icon_lookup

var icons = icon_lookup.IconResolver.init(env, mem.heap, null)
defer icons.deinit()

if icons.lookup("firefox") |path| {
    std.io.println(path)
}
```

The third argument is the preferred theme, or `null` for the default order. `otter_desktop.apps.icon_theme.detect` reads the theme the user configured. See [otter-utils](/developers/libraries/otter-utils).

## Lua

`otter.desktop.apps` lists and launches applications. `launch` needs the `spawn` capability.

```lua
local apps = require("otter.desktop.apps")

for _, app in ipairs(apps.search("term", 5)) do
  print(app.id, app.name, app.icon)
end

apps.subscribe(function()
  -- the installed applications changed
end)

apps.launch("otter-term")   -- needs "spawn"
```

| Module | Functions |
| --- | --- |
| `otter.desktop.apps` | `list()`, `find(id)`, `search(query, limit)`, `actions(id)`, `subscribe(f)`, and `launch(id, action, uris)` with `spawn`. |
| `otter.desktop.xdg_open` | `content_type(uri)`, `applications(uri, type)`, and `open(uri)` and `open_with(app_id, uri, type)` with `spawn`. |
| `otter.desktop.icons` | `lookup(name)`, `lookup_in_theme(theme, name)`, `lookup_symbolic(name, symbolic_first)`, `themes()`, `set_theme(name)`. |

Each plugin has its own icon resolver, so one plugin's theme choice does not affect another.
