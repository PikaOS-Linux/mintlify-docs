## PAM authentication

Native authentication lives under `otter_desktop.pam`. `pam.PamAuth.authenticate(service, user, password)` returns `PamResult`. PAM support is controlled by `enable_pam`.

Session operations use `pam_session.Session(Backend)` with a backend owned by value. Conversations are borrowed through `conv.Conversation` for the duration of a PAM call; no application pointer remains in `appdata_ptr`.

Account checks, credential setup/deletion, and session open/close operations receive a conversation too. `conv.Silent` drops messages and refuses prompts when interaction is not allowed. Test fixtures can select a private PAM configuration directory.

## Session discovery and launch

`otter_desktop.apps.session_catalog` discovers session entries. `session_launcher` handles session launching. Session discovery does not mean Otter Shell supplies the compositor named by an entry.

The greeter uses Hyprland for the login screen only. User sessions select their own compositor/session.

## D-Bus authentication and power

`dbus.logind`, `logind_seats`, `accounts_service`, `power_actions`, `polkit_agent`, and `fprintd` cover the corresponding services. Keep cancellation, prompts, and service errors explicit in the app's lifecycle.

## Lua boundary

Lua desktop bindings expose selected status and power operations, not raw PAM conversation or authentication handles. `otter.desktop.logind.suspend`, `reboot`, and `poweroff` require `power`. Never invoke these actions as documentation verification.
