## Input components

`seat.SeatState`, `keyboard.Keyboard`, and `text_input.TextInput` apply hub records during `pump` and expose queues. They do not store app callback/context pointers.

`SeatState` retains pointer coordinates, current surface ID, and protocol serials. `Keyboard` owns keymap/repeat state and exposes an optional repeat descriptor. Drive repeat from that descriptor rather than a polling timer.

## Preserve input order

Seat, keyboard, and IME queues are separate. Use `input_order.next` to merge their heads by hub sequence number when ordering matters. Draining all pointer events before all key events can reorder one compositor dispatch.

## IME

`TextInput` supports preedit, composition checks, cursor rectangles, enable/disable, and commit operations. Suppress direct key insertion while composition owns the text.

Password controls call `set_content(.password)`. This sends sensitive/hidden-text hints and password purpose to the compositor. A change while enabled still needs a commit.

## Clipboard and drag-and-drop

`clipboard`, `clipboard_transfer`, `clipboard_dnd`, and `clipboard_monitor` separate transfer and ownership policy. Drain DnD events and answer through explicit acceptance/finish methods instead of callback return values.

## Injection

`virtual_keyboard.TextInjector` provides explicit typing/key/chord operations with borrowed connection and I/O. Availability depends on the compositor's virtual-input protocols; the library does not bypass that policy.

Lua `otter.wayland.clipboard()` and `set_clipboard` both require `clipboard`. Window/workspace actions require `wayland-actions`. A readable public output list does not imply either capability.
