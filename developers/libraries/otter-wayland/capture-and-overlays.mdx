## Capture modules

Capture lives in flat leaf modules such as `capture_output`, `capture_session`, `capture_buffer`, `capture_formats`, `capture_color`, and `capture_hdr`. The Zig `capture` root namespace is not available.

Capture sources depend on compositor-advertised protocols. Keep source selection, buffer lifetime, and completion/failure events explicit.

## Shared selectors

`selection_overlay` is the shared region/point selection implementation. `capture_overlay` manages its Wayland surface. Apps use the supplied presets for screenshots, product shots, recording, or point selection instead of maintaining separate selectors.

The overlay composites pixels directly; it is not a Surface Description node tree. Editor integration uses the `selection_overlay.Editor` interface, not a raw callback/context pair.

## Outputs and scale

`capture_output.OutputList` is the output state owner. It tracks mode, position, transform, integer scale, and available logical geometry.

Exact scale derives from mode/logical dimensions and snaps to the protocol grid. Integer `wl_output.scale` is a ceiling. Unknown exact scale is reported as unknown, not guessed as 1.

## Lua boundary and verification

`otter.wayland` exposes output/window/workspace information and selected actions. It does not expose native capture-session or selection-overlay constructors.

Verify capture behavior in isolated headless sessions or direct-render fixtures. Never start a selector or screenshot operation against the developer's real Wayland session during tests.
