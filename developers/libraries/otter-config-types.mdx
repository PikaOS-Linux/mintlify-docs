`otter-config-types` defines defaulted application schemas without opening services or drawing UI. Import an application leaf module, for example `otter_config_types.bar` or `otter_config_types.term`.

Colors come from `otter_geo.color`. Text fields use `otter_conf.text.Text`; configs containing owned text have `deinit()`. Plain numeric/color-only configs remain copyable values.

`otter_config_types.fields` exposes `is_known_field`, `field_needs_quoting`, and `get_enum_field_names` for editors.

## Lua schema access

The separate `otter_config_types_lua` package exposes `otter.config.schema`, not `otter.config`. It requires no capability because it performs no I/O.

- `apps()` lists the 22 schema names.
- `file(app)` returns the config file name or greeter's system path.
- `defaults(app)` returns a nested defaults table.
- `parse(app, text)` returns the typed table or `nil, error_name`.
- `field(app, key)` returns quoting and enum metadata, or nil.

File reads, watches, and typed writes belong to `otter_conf_lua`.
