## Presets

Import `otter_theme.presets`. `presets` is an eleven-entry static table; `find_preset(name)` returns an optional preset value. Presets supply colors, while profiles supply broader theme structure.

## Load a theme

`loader.load_theme(env, alloc)` returns a `Theme`. `load_theme_from_path` reads an explicit root. Functions that resolve HOME or XDG paths take `std.Env` explicitly.

`load_theme_graph` and `load_theme_graph_from_path` return the resolved theme plus owned dependency paths. `LoadedTheme.deinit()` consumes both.

`get_theme_config_path(env, &mut buf)` resolves the user root, respecting an absolute `XDG_CONFIG_HOME`. `get_system_theme_path(&mut buf)` resolves the system fallback.

Loading an existing layered theme is read-only. One exception is legacy flat-theme migration: `load_theme_graph_from_path` can save the old root as `<path>.legacy`, write `custom-colors.conf`, `custom-layout.conf`, and `custom-spacing.conf`, then rewrite the root to select those layers. Use a temporary fixture directory when testing legacy loads.

`normalize_theme_config` is a separate write operation reserved for designated Settings/Theme Gen workflows, not ordinary app startup or reload callbacks.

## Hot reload

Use `otter_theme.theme_watcher.ThemeWatcher`:

1. Initialize with environment and allocator, or `init_from_path` for a fixture root.
2. Watch `get_fd()` in the app loop.
3. Drain changes and reload the complete graph.
4. Retain the previous valid theme if parsing or import resolution fails.
5. Refresh watched dependencies with the environment after a successful graph change.

`ThemeWatcher` does not keep a hidden environment singleton. It watches the root and loaded layer/import paths.

## Lua preset writes

`otter.theme.use_preset(name, on_done)` requires `theme-write`. It queues durable writes outside the Lua watchdog budget and reports completion through the host loop. Only one preset write runs at a time. Read-only subscribers do not gain write access.
