## SplatHash

SplatHash modules live under `otter_tools_core.splathash`: `encode`, `decode`, `pack`, `gaussian`, `oklab`, and generated lookup tables.

Import a leaf module for the operation you need. There is no aggregate `splathash` barrel; `SeedColor` belongs to `splathash.decode`.

Sampling and color conversion stay separate from image loading. Supply decoded/sampled input from the render package when extracting wallpaper colors.

## Semantic palettes

`otter_tools_core.theme_palette` and its supporting modules implement palette roles and generation. Supporting modules include `roles`, `trig`, `material_you`, `analogous`, `vibrant`, `monochromatic`, `direct`, and `temperature`.

Palette generation supplies colors. It must not rewrite profile geometry, typography, density, or other layout decisions.

## Small-tool configuration

`app_configs` supplies schemas for small tools. `config` supplies shared user/system path and load/save behavior with explicit environment:

- `user_path` / `system_path` build config locations.
- `load_or_create` loads application defaults and user state.
- `save_user` writes the user config.

String-bearing configs use `otter_conf.text.Text` and consuming cleanup. Do not write normalized files under `/etc/otter-shell` from a user application.

## Lua boundary

The tools Lua package exposes selected calculation/color/calendar/weather/search helpers. It does not expose a general native SplatHash or theme-palette constructor. Use `otter.theme` for served theme snapshots and controlled preset changes.
