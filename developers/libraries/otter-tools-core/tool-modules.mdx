## Native modules

| Module                                      | Purpose                                            |
| ------------------------------------------- | -------------------------------------------------- |
| `calc`                                      | `eval` expressions; nesting capped at 256          |
| `duration`                                  | `parse_seconds`, bounded `format_compact`          |
| `calendar`                                  | Dates, weekdays, month shifts/grids                |
| `emoji`                                     | 3944-entry static catalog and bounded index search |
| `clip_history`, `clipboard`                 | History policy and clipboard helpers               |
| `record`                                    | Capture/encoder/backend selection                  |
| `weather`                                   | URLs, parsed forecasts, cache format               |
| `web_search`                                | Search URL construction and owned result parsing   |
| `nightlight`                                | Schedule, Kelvin/gamma, command/state protocol     |
| `search_client`, `assist_client`, `framing` | Local socket protocols and streamed events         |
| `knowledge`                                 | Read-only zidx knowledge sessions                  |

`calc.eval` returns `Error!f64`, including `TooDeep`. `emoji.search` writes catalog indices into caller output rather than returning pointers to entries.

`knowledge.Session.init(env, alloc, root)` owns mapped index/model state. Search results own their strings. Index writers remain outside this native read API.

## Search engine

The separate `otter_tools_search_engine` package contains `file_index`, `query`, `scanner`, `finder`, `content`, `fuzzy`, `scoring`, and `partial_sort`.

Searchers borrow the current index per search; they do not retain an index pointer. Cancel and join readers before mutating/replacing the live index.

## Lua modules

`otter_tools_core_lua` provides `otter.tools.calc`, `.duration`, `.color`, `.emoji`, `.calendar`, `.weather`, and `.search`.

Read-only computations need no capability. `.search` requires `desktop-search`. Weather cache paths and search socket paths are configured by the host. A module's presence does not imply the plugin can fetch arbitrary URLs or read arbitrary files.
