Otter Shell apps build on shared libraries written in otr. Each library is its own repository with its sources in `otr/`. An app names the libraries it uses in its `otr.toml`, and the compiler links them into the app statically.

## Library map

The package name is the import root. An app that depends on `otter-utils` writes `import otter_utils.log`.

| Library | Package | Purpose |
| --- | --- | --- |
| [otter-geo](/developers/libraries/otter-geo) | `otter_geo` | Geometry types, transforms, colors |
| [otter-utils](/developers/libraries/otter-utils) | `otter_utils` | Logging, XDG paths, icon lookup, i18n, build steps |
| [otter-conf](/developers/libraries/otter-conf) | `otter_conf` | Flat key-value config parser, loader, serializer, watcher |
| [otter-config-types](/developers/libraries/otter-config-types) | `otter_config_types` | Every app's config schema and the Settings field metadata |
| [otter-theme](/developers/libraries/otter-theme) | `otter_theme` | Colors, layout, spacing, theme loading and watching |
| [otter-render](/developers/libraries/otter-render) | `otter_render` | Fonts, text shaping, images, command lists, the CPU rasterizer |
| [otter-wayland](/developers/libraries/otter-wayland) | `otter_wayland` | Wayland client: surfaces, input, clipboard, outputs, capture |
| [otter-ui](/developers/libraries/otter-ui) | `otter_ui` | Surface Description frames, controls, scroll views |
| [otter-vte](/developers/libraries/otter-vte) | `otter_vte` | Terminal cell and glyph rendering |
| [otter-desktop](/developers/libraries/otter-desktop) | `otter_desktop` | Desktop entries, MIME, D-Bus services, system information, PAM |

| [otter-crypto](/developers/libraries/otter-crypto) | `otter_crypto` | Ciphers, hashes, signatures, key exchange |

| otter-media | `otter_media` | Media engine: demux, decode, A/V clock, subtitles |
| otter-syntax | `otter_syntax` | Syntax highlighting for 35 languages |

## Depend on a library

Add the library to `[dependencies]` with the path to its `otr/` folder. This is the dependency table of the `otter-examples` starter:

```toml otr/otr.toml
[dependencies]
otter_geo = { path = "../../otter-geo/otr" }
otter_utils = { path = "../../otter-utils/otr" }
otter_theme = { path = "../../otter-theme/otr" }
otter_render = { path = "../../otter-render/otr" }
otter_wayland = { path = "../../otter-wayland/otr" }
otter_wayland_render = { path = "../../otter-wayland/otr/render" }
otter_ui = { path = "../../otter-ui/otr" }
```

Then import the modules you need. The libraries have no package-wide root module, so you import each module by its path:

```otr
import otter_geo.rect as geo
import otter_render.color
import otter_theme.theme
import otter_ui.style
import otter_ui.ui_frame

const Rect = geo.Rect
const Color = color.Color
const Theme = theme.Theme
```

A module's name after the last dot is how you refer to it, and `as` renames it. Function and module names use `snake_case`.

Library functions that read the environment or do I/O take a `std.Env` or its `env.io`, which your `main` receives:

```otr
t := loader.load_theme(env, mem.heap)
defer t.deinit()
f := try font.Font.init(mem.heap, env.io, .{ font_family: t.globals.font_family.as_str() })
```

A value with a `deinit` method is a resource. The compiler rejects any path that does not consume it, so call `deinit` once, usually with `defer`. See [Ownership and borrowing](/otr/memory/ownership-and-borrowing).

## Sub-packages

Some repositories hold more than one package. A sub-package has its own `otr.toml` in a subfolder, so an app links only the parts it uses.

| Package | Path | Purpose |
| --- | --- | --- |
| `otter_wayland_core` | `otter-wayland/otr/core/` | The surface-free part of the Wayland client, for daemons that draw nothing |
| `otter_wayland_render` | `otter-wayland/otr/render/` | SHM renderer, layer popups, capture and selection overlays |
| `otter_render_formats` | `otter-render/otr/formats/` | AVIF, HEIC, JPEG XL, TIFF, and camera RAW decoding |
| `otter_desktop_pipewire` | `otter-desktop/otr/pipewire/` | PipeWire audio devices, playback, and the stream sink |
| `otter_ui_widgets` | `otter-ui/widgets-otr/` | The bar widgets, one folder per widget |
| `otter_ui_volume` | `otter-ui/otr/volume/` | The volume widget wired to PipeWire |
| `otter_media_tags` | `otter-media/otr/tags/` | Tag reader for audio files |
| `otter_tools_search` | `otter-tools-core/otr/search/` | Search indexing |
| `otter_ocr` | `otter-tools-core/otr/ocr/` | OCR |
| `otter_tools_spell` | `otter-tools-core/otr/spell/` | Spell checking over Enchant |

`otter_wayland` includes every module of `otter_wayland_core` under its own name. Depend on the core package alone when your program has no surface.

## Lua bindings

A library exposes itself to Lua through a separate package in its `otr/lua/` folder. An app that hosts Lua adds the binding packages it wants to its manifest. An app that hosts no Lua never links LuaJIT.

## Build options

Libraries declare compile-time options in the `[options]` table of their `otr.toml`. An app sets the value for its own build in its manifest, or with `-D name=value` on the `otr build` command line.

| Option | Declared by | Default | Purpose |
| --- | --- | --- | --- |
| `enable_dbus` | `otter_desktop` | `true` | Include the D-Bus services |
| `enable_pipewire` | `otter_desktop`, `otter_cue` | `true` | Include PipeWire support |
| `enable_pam` | `otter_desktop` | `false` | Link PAM for authentication |
| `pipewire` | `otter_desktop_pipewire` | `static` | Link the vendored static PipeWire, or `system` for the system library |
| `enable_render_text` | `otter_render` | `true` | Include fonts and text shaping |
| `enable_render_svg` | `otter_render` | `true` | Include SVG decoding |
| `enable_render_jpeg` | `otter_render` | `true` | Include JPEG decoding |
| `enable_render_wide_image_formats` | `otter_render` | `true` | Include WebP decoding |

The defaults in the table are the library's own. The `otter-examples` starter turns off `enable_dbus`, `enable_pipewire`, `enable_render_jpeg`, and `enable_render_wide_image_formats` in its manifest because its card uses none of them.

## Source and checks

Each library is a repository under [git.pika-os.com/otter-shell](https://git.pika-os.com/otter-shell). Most libraries have an `otr/API.md` that lists the public modules. The `pub` declarations in the source are the authority.

From a library's repository root, `otr run otr/build.otr -- check` type-checks every module and checks formatting. The doc comment at the top of `otr/build.otr` lists the other steps. See [Building](/developers/building).
