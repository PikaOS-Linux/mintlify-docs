Zoolander calls a connected display an output, or a monitor in the Lua API. You configure outputs with `zl.output_rule` and read their state with the monitor query functions.

```lua
zl.output_rule({
    output = "DP-3",
    width = 3840,
    height = 2160,
    refresh = 240,
    x = 0,
    y = 0,
    scale = 2,
})
```

## Output names

A rule matches an output by its exact name. On real hardware, Zoolander names outputs after the DRM connector, as `<type>-<number>`:

| Connector | Example name |
| --- | --- |
| DisplayPort | `DP-1`, `DP-2` |
| HDMI | `HDMI-A-1` |
| Laptop panel | `eDP-1` |
| DVI | `DVI-D-1`, `DVI-I-1` |
| VGA | `VGA-1` |
| Other connector types | `LVDS-1`, `DSI-1`, `Virtual-1`, `USB-1` |

When Zoolander runs nested inside another compositor, its output is `NESTED-1`. With the headless backend, it is `HEADLESS-1`.

To see the names on your machine, run:

```bash
zoolanderctl eval "local o={} for i=0,zl.monitor_count()-1 do o[#o+1]=zl.monitor_info(i).name end return table.concat(o,' ')"
```

Displays that mark themselves as non-desktop, such as VR headsets, are not lit as outputs. Zoolander offers them for DRM leasing instead.

## zl.output_rule

```lua
zl.output_rule(options)
```

Adds a rule for one output. You can have up to 16 rules, one per output name. A second rule for the same name, a second rule with `primary = true`, or a 17th rule raises the error `zl.output_rule: duplicate, a second primary, or too many rules`.

Only `output` is required. A field you leave out keeps what the output has now: its current mode, position, scale and transform, and for the presentation fields the global value from `zl.set_presentation`.

| Name | Description | Type | Default |
| --- | --- | --- | --- |
| `output` | Output name, 1 to 127 bytes. | string | required |
| `width` | Mode width in pixels, 1 to 16384. | integer | the current mode |
| `height` | Mode height in pixels, 1 to 16384. | integer | the current mode |
| `refresh` | Refresh rate in Hz, 1 to 1000. Fractions such as `59.94` are allowed. | number | the current mode |
| `x` | Horizontal position in the global layout, in logical pixels. -100000 to 100000. | number | the current position |
| `y` | Vertical position in the global layout, in logical pixels. -100000 to 100000. | number | the current position |
| `scale` | Scale factor, 0.01 to 8. Fractional values such as `1.5` work. | number | the current scale |
| `transform` | Rotation and flip. See [Transforms](#transforms). | string | the current transform |
| `enabled` | `false` turns the output off. See [Turn an output off](#turn-an-output-off). | boolean | `true` |
| `primary` | Makes this the primary output. See [Primary output](#primary-output). | boolean | `false` |

Set `width`, `height` and `refresh` together or not at all, and `x` and `y` together or not at all. Otherwise the call raises `zl.output_rule: width, height and refresh go together` or `zl.output_rule: x and y go together`. Zoolander rounds `x` and `y` to whole pixels and stores `refresh` in millihertz.

The rule also takes per-output presentation settings. See [Presentation per output](#presentation-per-output).

A value out of range raises an error. It is never clamped. An unknown field logs `zoolander: zl.output_rule: unknown field <name>` and the rule still applies.

### Mode selection

Zoolander looks for an advertised mode with exactly `width` by `height` and a refresh rate within 1 Hz of `refresh`. If it finds one, it uses it. If not, it asks the output for a custom mode with those values. Prefer a mode that the monitor lists. You can see them with `wlr-randr`.

### Positions and scale

`x` and `y` are in logical pixels, after scaling. A 3840 by 2160 output at scale 2 is 1920 by 1080 logical pixels wide. The next output to its right starts at `x = 1920`:

```lua
zl.output_rule({ output = "DP-3", width = 3840, height = 2160, refresh = 240, x = 0, y = 0, scale = 2 })
zl.output_rule({ output = "DP-2", width = 2560, height = 1440, refresh = 240, x = 1920, y = 0, scale = 1 })
```

`zl.focus_monitor` and `zl.move_window_direction` use these positions to find the monitor in a direction.

### Transforms

| Value | Effect |
| --- | --- |
| `"normal"` | No rotation. |
| `"rotate_90"` or `"90"` | Rotate 90 degrees. |
| `"rotate_180"` or `"180"` | Rotate 180 degrees. |
| `"rotate_270"` or `"270"` | Rotate 270 degrees. |
| `"flipped"` | Mirror horizontally. |
| `"flipped_90"` | Mirror, then rotate 90 degrees. |
| `"flipped_180"` | Mirror, then rotate 180 degrees. |
| `"flipped_270"` | Mirror, then rotate 270 degrees. |

```lua
zl.output_rule({
    output = "HDMI-A-1",
    width = 1920, height = 1080, refresh = 60,
    x = 2560, y = 0,
    transform = "90",
})
```

### Turn an output off

`enabled = false` turns the output off. When a reload drops that rule, or the rule no longer sets `enabled = false`, the output comes back on at its last placement. An output that a client turned off through wlr-output-management stays off.

```lua
zl.output_rule({ output = "HDMI-A-1", enabled = false })
```

### Primary output

`primary = true` makes the output the primary one. X11 windows and popups that do not pick an output open on it, and `zoolanderctl monitors` lists it first. Without such a rule, the first output that connected is primary. Only one rule may set it. A rule with `enabled = false` cannot, and raises `zl.output_rule: a disabled output cannot be primary`.

### Presentation per output

These fields override the global [`zl.set_presentation`](/zoolander/configuring/variables) value for this output. A field you leave out uses the global value.

| Name | Description | Type |
| --- | --- | --- |
| `vrr` | `off`, `always`, `fullscreen`, `fullscreen_game`, or `0` to `3`. | string or integer |
| `hdr` | `off`, `auto` or `always`. | string |
| `bitdepth` | `8` or `10`. See [Bit depth](#bit-depth). | integer |
| `sdr_brightness` | 0.1 to 4. | number |
| `sdr_saturation` | 0 to 2. | number |
| `sdr_min_luminance` | 0 to 10 nits. | number |
| `sdr_max_luminance` | 40 to 1000 nits. | number |
| `sdr_eotf` | `srgb`, `gamma22` or `gamma24`. | string |
| `min_luminance` | 0 to 10 nits. Replaces the EDID value. | number |
| `max_luminance` | 80 to 10000 nits. Replaces the EDID value. | number |
| `max_avg_luminance` | 50 to 10000 nits. Replaces the EDID value. | number |

`min_luminance`, `max_luminance` and `max_avg_luminance` become the target luminances that clients see. `max_luminance` is also the tone-mapping peak. The HDR metadata sent to the display uses `min_luminance` and `max_luminance` for the mastering range, `max_luminance` for MaxCLL and `max_avg_luminance` for MaxFALL, both for Zoolander's own metadata and for a fullscreen client's. Left out, the EDID values apply. For the tone-mapping peak, an EDID maximum of exactly 100 nits counts as unknown, and the peak is then 1000 nits.

```lua
zl.output_rule({ output = "DP-1", hdr = "always", vrr = "fullscreen_game", max_luminance = 600 })
```

#### Bit depth

Without `bitdepth`, the output scans out 8 bits per channel in SDR and 10 while HDR is on.

- `10` also scans SDR out at 10 bits, on outputs that are not HDR-capable too, when the connector's `max bpc` reaches 10, the output renders on the GPU and a 10-bit buffer can be allocated.
- `8` forces 8 bits, so HDR never turns on for that output. `bitdepth = 8` with `hdr = "always"` raises an error. On an output without a `max bpc` property, `8` is ignored.

A depth the output cannot use logs a warning on each reload, and the driver's depth applies instead. Removing the setting hands the depth back to the driver on the next reload.

### What output rules do not set

`zl.output_rule` has no option for mirroring. To change an output while Zoolander runs without editing the config, use a client of the wlr-output-management protocol, such as `wlr-randr` or `kanshi`.

## When rules apply

- At startup, and each time an output connects, Zoolander applies every rule whose output is present. A rule turns its output on, unless it sets `enabled = false`.
- When you reload the config, Zoolander compares the new rules with the ones it last applied. If any rule changed, it applies the whole set again. If none changed, it leaves outputs alone, so a reload does not undo a change you made with `wlr-randr`.
- A rule for an output that is not connected waits until that output appears.

### Outputs without a rule

An output with no rule keeps the mode the backend picks, at scale 1 with no transform. Zoolander places it so it does not overlap the others:

1. An output that was unplugged and plugged back in returns to its earlier position, scale and transform.
2. An output placed earlier in this session returns to that position.
3. Any other output goes to the right of the rightmost output, at `y = 0`.

## Direct scanout

When one fullscreen window covers an output, Zoolander can hand its buffer straight to the display plane instead of drawing a frame. This is direct scanout, controlled by `direct_scanout` in `zl.set_presentation` and on by default.

- A game whose buffer is tagged with the output's own colour encoding scans out, such as a PQ game on an HDR output.
- An SDR game fullscreen on an HDR output scans out where the plane has a colour pipeline. The display engine converts SDR to PQ, as the renderer would.
- `XBGR8888` and opaque `ABGR8888` buffers, which many Vulkan games present, scan out as well as `XRGB8888`.

`zoolanderctl monitors` shows a `direct scanout:` line per output with `active` or the reason the last frame was composited, and whether the plane has a colour pipeline:

```text
  direct scanout: active (plane converts colour), plane colour pipeline=true
```

See [Direct scanout does not engage](/zoolander/troubleshooting#direct-scanout-does-not-engage) for each reason and the GPU support for colour conversion.

## Hotplug

When an output connects:

1. Zoolander applies its rule, if there is one.
2. If the output was connected earlier in the session, its workspaces and their windows come back to it.
3. Otherwise it gets a new workspace called `1`.
4. Handlers for the `output_added` event run with a monitor table for the new output.

When an output disconnects:

1. Handlers for the `output_removed` event run with a monitor table for that output.
2. Zoolander moves special workspaces that were on it to the first remaining output.
3. Its regular workspaces and their windows stay parked until the output returns. If you switch to a parked workspace by name with `zl.workspace`, Zoolander shows it, with its windows, on the active monitor.
4. If the last output disconnects and a different one connects, the new output takes the windows of the last one.

React to hotplug with `zl.on`:

```lua
zl.on("output_added", function(monitor)
    zl.workspace_on_monitor(monitor.name, "1")
end)

zl.on("output_removed", function(monitor)
    zl.exec_command("notify-send 'Disconnected " .. monitor.name .. "'")
end)
```

The [split workspaces recipe](/zoolander/configuring/workspaces#split-workspaces-recipe) shows a full hotplug handler. Events are covered on [Hooks and events](/zoolander/configuring/hooks-and-events).

## Monitor queries

| Function | Arguments | Description |
| --- | --- | --- |
| `zl.monitor_count()` | none | Number of connected monitors. Returns `0` before startup. |
| `zl.monitor_info(index)` | `index` | A monitor table for the monitor at zero-based `index`, or `nil` if there is none. |
| `zl.active_monitor_index()` | none | Zero-based index of the active monitor, or `-1` when there is none or before startup. |
| `zl.monitor_at_cursor_index()` | none | Zero-based index of the monitor under the pointer, or `-1` when the pointer is in a gap or before startup. |
| `zl.focus_monitor(direction)` | `"left"`, `"right"`, `"up"` or `"down"` | Moves focus and the pointer to the nearest monitor in that direction. See [Dispatchers](/zoolander/configuring/dispatchers#focus_monitor). |

Indexes follow the order in which outputs connected. Disconnected outputs are skipped, so an index can change after hotplug. Look monitors up by `name` if you need a stable key.

The active monitor is the one with focus. A monitor becomes active when keyboard focus lands on one of its windows, or when the pointer moves onto it, even if it has no windows.

### Monitor table fields

`zl.monitor_info` returns a table with these fields. The `output_added` and `output_removed` handlers get the same table.

| Field | Description | Type |
| --- | --- | --- |
| `id` | The output's `wl_output` global name in the Wayland registry. | integer |
| `name` | Output name, such as `DP-1`. | string |
| `mirror` | Whether the output mirrors another. Zoolander currently always reports `false`. | boolean |
| `active_workspace` | `{ name = string }`, the regular workspace shown on the monitor. `name` is `""` when there is none. | table |

```lua
local function monitors()
    local list = {}
    for i = 0, zl.monitor_count() - 1 do
        list[#list + 1] = zl.monitor_info(i)
    end
    return list
end

zl.bind(zl.MOD_LOGO, "m", function()
    local current = zl.monitor_info(zl.active_monitor_index())
    zl.exec_command("notify-send '" .. current.name .. ": " .. current.active_workspace.name .. "'")
end)
```

## zl.set_output_size

```lua
zl.set_output_size(width, height) -> boolean
```

Sets the size of the first output, in pixels. Both arguments must be integers. Called at the top level of the first config run, before the compositor starts, it records the size for startup and returns `true`. Called later, it asks the first output for a custom mode of that size and returns whether the request went through. This is most useful for the nested and headless backends, where the output is a window or a buffer. For a real monitor, use `zl.output_rule`.

```lua
zl.set_output_size(1600, 900)
```

## Examples

### Laptop with an external monitor above it

```lua
zl.output_rule({ output = "eDP-1", width = 2880, height = 1800, refresh = 120, x = 0, y = 1080, scale = 2 })
zl.output_rule({ output = "DP-1", width = 1920, height = 1080, refresh = 60, x = 0, y = 0, scale = 1 })
```

The laptop panel is 1440 by 900 logical pixels at scale 2. The external monitor sits above it, so the panel starts at `y = 1080`.

### Per-machine rules

`require` loads Lua modules from beside `init.lua`. Use a global or a module to pick rules per machine:

```lua
-- monitors.lua
if ZL_AMD_VM_TEST then
    zl.output_rule({ output = "HDMI-A-1", width = 1920, height = 1080, refresh = 240, x = 0, y = 0 })
    zl.output_rule({ output = "DP-1", width = 1920, height = 1080, refresh = 240, x = 1920, y = 0 })
    return
end

zl.output_rule({ output = "DP-3", width = 3840, height = 2160, refresh = 240, x = 0, y = 0, scale = 2 })
zl.output_rule({ output = "DP-2", width = 2560, height = 1440, refresh = 240, x = 1920, y = 0, scale = 1 })
```

```lua
-- init.lua
require("monitors")
```

`ZL_AMD_VM_TEST` is an ordinary Lua global that the config sets for one machine. Zoolander gives it no meaning. Set it before `require("monitors")` runs.

### Bind keys to monitors

```lua
zl.bind(zl.MOD_LOGO + zl.MOD_CTRL, zl.KEY_LEFT, function() zl.focus_monitor("left") end)
zl.bind(zl.MOD_LOGO + zl.MOD_CTRL, zl.KEY_RIGHT, function() zl.focus_monitor("right") end)
zl.bind(zl.MOD_LOGO + zl.MOD_SHIFT + zl.MOD_CTRL, zl.KEY_RIGHT, function() zl.move_window_direction("right") end)
```

`zl.move_window_direction` moves a window to the next monitor once it reaches the edge of the layout.
