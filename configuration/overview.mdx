Every Otter Shell application reads its settings from a plain-text config file in `~/.config/otter-shell/`. Files use `key = value` syntax and hot-reload via inotify for most daemons — no restart required.

## File format

```conf
# Comments start with #
font_size = 14
font_family = "IoskeleyMono Nerd Font"
url_enabled = true
```

<Note>
  Quote string values with double quotes. Booleans are `true` or `false`. An empty string `""` falls back to the compiled default.

  On first launch, apps that use `otter-conf` normalize the config file — missing keys are added with defaults and unknown keys are removed.
</Note>

## otter-settings

`otter-settings` provides a graphical editor with a tab for each app config. Changes write to the same `~/.config/otter-shell/*.conf` files, so manual edits and GUI edits are interchangeable.

```bash
otter-settings
```

Features include a theme browser with 12 built-in presets, drag-and-drop bar widget layout, and search across all config fields.

## Hot reload

Most daemons watch their config (and often `theme.conf`) with inotify:

- **otter-bar**, **otter-notifications**, **otter-wallpaper**, **otter-osd**, **otter-idle** — reload on save without restart
- **otter-term** — hot-reloads fonts, colors, padding, and scrollback
- **otter-transcribe** — reloads settings and watches `theme.conf`

## System-wide defaults

Lookup order (example for `otter-term`):

1. `~/.config/otter-shell/otter-term.conf` *(user — highest priority)*
2. `/etc/otter-shell/otter-term.conf` *(system defaults)*
3. Compiled-in defaults

Administrators can set defaults in `/etc/otter-shell/` without touching home directories.
