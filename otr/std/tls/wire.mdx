The byte formats of `std.tls`: a bounds-checked reader over a received message, writers
for the length-prefixed vectors TLS nests everything in, and the numbers the protocol
gives versions, suites, groups, signature schemes, extensions and alerts. Readers return
`error.DecodeError` for anything short or overlong, so a parser written with them cannot
read past what the peer sent.

```otr
import std.tls.wire
```

## DecodeError

```otr
const DecodeError = error { DecodeError }
```

## Error

```otr
const Error = error
```

What can go wrong in `std.tls`.

| Member | Type | Description |
| --- | --- | --- |
| <code>DecodeError</code> |  | A record or handshake message the peer sent is malformed. |
| <code>UnexpectedMessage</code> |  | The peer sent a message the protocol does not allow at this point. |
| <code>RecordOverflow</code> |  | A record longer than the protocol allows. |
| <code>BadRecordMac</code> |  | A record failed authentication: it was altered, or keys disagree. |
| <code>IllegalParameter</code> |  | The server chose something the client did not offer, or a value the protocol forbids. |
| <code>UnsupportedExtension</code> |  | The server sent an extension the client did not offer. |
| <code>NoApplicationProtocol</code> |  | The server picked an application protocol the client did not offer. |
| <code>HandshakeFailure</code> |  | The server refused renegotiation protection (a non-empty renegotiation_info). |
| <code>ProtocolVersion</code> |  | The server speaks no version the client accepts, or the downgrade guard of RFC 8446 §4.1.3 fired. |
| <code>DecryptError</code> |  | The server's handshake signature or Finished MAC is wrong. |
| <code>AlertReceived</code> |  | The server sent a fatal alert; `Client.alert` holds its code. |
| <code>Closed</code> |  | The connection has failed or closed, or this end has closed it. |
| <code>MessageTooLong</code> |  | More application data than `seal`'s buffer or one record holds. |
| <code>InvalidHost</code> |  | The host name is empty or longer than DNS allows. |
| <code>NoEntropy</code> |  | The kernel's random source failed. |
| <code>b</code> | <code>[]u8</code> |  |
| <code>pos</code> | <code>usize</code> |  |

## Suite

```otr
const Suite = struct
```

A cipher suite: its record AEAD, the hash of its key schedule or PRF, the version it
belongs to and, for TLS 1.2, whether the server signs with an ECDSA (or Ed25519) key
rather than an RSA one.

| Field | Type |
| --- | --- |
| <code>id</code> | <code>u16</code> |
| <code>aead</code> | <code>keys.Aead</code> |
| <code>hash</code> | <code>sha2.Hash</code> |
| <code>tls13</code> | <code>bool</code> |
| <code>ecdsa</code> | <code>bool</code> |

## suites

```otr
const suites = [9]Suite
```

The suites offered, in order of preference: AES-GCM first, since the AEADs run it on the
CPU's AES instructions; RFC 8446 and RFC 9325's recommended TLS 1.2 suites, all with
forward secrecy and an AEAD.

## find_suite

```otr
fn find_suite(id: u16, tls13: bool) ?Suite
```

The suite `id` of the version asked for, or null when it was not offered.

## Scheme

```otr
const Scheme = struct
```

A signature scheme offered in `signature_algorithms`, the certificate signature it is,
and the EC key it needs in TLS 1.3, which binds ECDSA schemes to one curve.

| Field | Type | Description |
| --- | --- | --- |
| <code>id</code> | <code>u16</code> |  |
| <code>alg</code> | <code>x509.SigAlg</code> |  |
| <code>curve</code> | <code>x509.KeyAlg</code> |  |
| <code>legacy</code> | <code>bool</code> | PKCS #1 v1.5 RSA, which TLS 1.3 allows in certificates but not in CertificateVerify. |
