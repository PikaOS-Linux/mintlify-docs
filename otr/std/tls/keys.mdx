The cryptography under `std.tls`: the running transcript hash, TLS 1.3's HKDF key
schedule (RFC 8446 §7.1), TLS 1.2's PRF (RFC 5246 §5), and record protection with the
three AEADs both versions share. Hashes are picked at run time by `sha2.Hash`, since the
cipher suite that names one arrives in the server's first message; each function then
runs the code compiled for that hash.

```otr
import std.tls.keys
```

## Transcript

```otr
const Transcript = struct
```

The hash of every handshake message so far. Until the server picks a suite both hashes
run; `choose` then stops the one that is not needed.

| Field | Type | Access |
| --- | --- | --- |
| <code>s256</code> | <code>sha2.Sha256</code> | Read-only |
| <code>s384</code> | <code>sha2.Sha384</code> | Read-only |
| <code>only</code> | <code>?sha2.Hash</code> | Read-only |

## extract

```otr

```

HKDF-Extract. An empty `ikm` stands for the string of zeros as long as the hash, which
is what the schedule feeds in where it has no PSK and after the handshake secret.

HKDF-Expand-Label: `out` filled from `secret` under "tls13 " + `label` and `context`.


```otr

```

The finished MAC of RFC 8446 §4.4.4 over `transcript_hash`, keyed from a handshake

## prf

```otr

```

TLS 1.2's PRF, P_hash of RFC 5246 §5, filling `out` from `secret` under `label` and the
seed `seed_a || seed_b`.

## Protection

```otr
const Protection = struct
```

One direction's record protection: the keyed AEAD, its IV and the record sequence
number, which every sealed or opened record advances. TLS 1.3 and TLS 1.2's
ChaCha20-Poly1305 xor the sequence number into a 12-byte IV (RFC 8446 §5.3, RFC 7905);
TLS 1.2's AES-GCM takes a 4-byte salt and an 8-byte explicit nonce sent in each record
(RFC 5288), for which this side sends its sequence number.

| Field | Type | Access |
| --- | --- | --- |
| <code>seq</code> | <code>u64</code> | Public |
| <code>explicit_nonce</code> | <code>bool</code> | Public |
| <code>keyed</code> | <code>Keyed</code> | Read-only |
| <code>iv</code> | <code>[12]u8</code> | Read-only |

### Protection.init

```otr
fn init(a: Aead, key: []u8, iv: []u8, explicit_nonce: bool) Protection
```

`iv` is 12 bytes, or the 4-byte salt when `explicit_nonce`.

### Protection.nonce

```otr
fn nonce(self: &Protection, explicit: []u8) [12]u8
```

The nonce of the next record. With an explicit nonce, `explicit` is the 8 bytes the
record carries.

### Protection.seal

```otr
fn seal(self: &mut Protection, buf: []mut u8, ad: []u8, n: &[12]u8) [16]u8
```

Encrypts `buf` in place under `nonce` and returns the tag.

### Protection.open

```otr
fn open(self: &mut Protection, buf: []mut u8, tag: &[16]u8, ad: []u8, n: &[12]u8) AuthError!void
```

Checks `tag` and decrypts `buf` in place; a forgery leaves `buf` as it was.

## master12


## keys12

```otr
fn keys12(h: sha2.Hash, a: Aead, master: &[48]u8, client_random: &[32]u8, server_random: &[32]u8) struct { Protection, Protection }
```

TLS 1.2's client and server protection from its master secret (RFC 5246 §6.3): the key
block is the client's key, the server's, then the client's IV and the server's.
