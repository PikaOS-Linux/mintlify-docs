The hello messages of `std.tls`: the ClientHello, written for TLS 1.3 alone or for 1.3
and 1.2, and the ServerHello and EncryptedExtensions read into what they say, each
extension refused when the client did not offer it or when it comes twice. What the
answers mean for the handshake is `tls.Client`'s to decide.

```otr
import std.tls.hello
```

## read_server_hello

```otr
fn read_server_hello(body: []u8) wire.Error!ServerHello
```

The ServerHello `body`. Extensions a server may not send in either version are refused.

## read_encrypted_extensions

```otr
fn read_encrypted_extensions(exts: []u8) wire.Error!?[]u8
```

The ALPN extension's body from EncryptedExtensions `exts`, if it has one: only
extensions a client may see there (RFC 8446 §4.3.1) and that this one offered, each
once.

## alpn_name

```otr
fn alpn_name(d: []u8, offer: ?[]static u8) wire.Error! []u8
```

The one protocol an ALPN extension's body names, which must be `offer`.
