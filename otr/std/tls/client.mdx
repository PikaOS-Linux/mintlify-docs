`std.tls`'s client as a state machine that does no I/O: the handshake of TLS 1.3 and
TLS 1.2 over `hello`, `peer`, `keys` and `record`, and application data, KeyUpdate and
alerts after it. `tls` re-exports what is public here.

```otr
import std.tls.client
```

## Recv

```otr
const Recv = struct
```

What `recv` did: how many bytes at the front of the buffer it used up (0 when they do
not yet hold a whole record), and where application data it decrypted lies in them.

### Client.init

```otr
fn init(alloc: mem.Allocator, host: str, options: hello.Options) Error!Client
```

Starts a handshake with `host`: the ClientHello is in `pending` when this returns.
`host` is the name the certificate must carry, and is sent as SNI unless it is an
IP address.


### Client.sent

```otr

```

Drops the first `n` bytes of `pending`, which the caller has sent.

### Client.close

```otr
fn close(self: &mut Client) void
```

Queues close_notify. Received data is still read until the server closes too.

### Client.recv

```otr
fn recv(self: &mut Client, buf: []mut u8) Error!Recv
```

Takes the record at the front of `buf`. Application data is decrypted in place and
its place returned; handshake messages advance the handshake, and any reply lands in
`pending`. After an error the connection is failed, and `pending` holds the alert
that tells the server why.

### Client.seal

```otr
fn seal(self: &mut Client, buf: []mut u8, n: usize) Error!record.Range
```

Seals the `n` bytes of application data at `buf[prefix_len..]` into one record, in
place, and returns where in `buf` the record lies; `buf` needs `prefix_len + n +
suffix_len` bytes. When the key has sealed its share of records, a KeyUpdate goes to
`pending` first and the record is sealed under the next key, so `pending` must be
sent before the record.
