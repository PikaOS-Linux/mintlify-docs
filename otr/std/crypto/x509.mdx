X.509 v3 certificates (RFC 5280): parsing, signature checks between certificates, and
host name matching (RFC 6125, by `hostname`). A `Certificate` records where each field lies in the
DER it was parsed from, so it is a small copyable value that borrows nothing; the
methods that read a field take that DER again.

Parsing is strict DER and rejects what RFC 5280 forbids: mismatched inner and outer
signature algorithms, repeated extensions, and critical extensions this module does
not enforce, since accepting a constraint without checking it would widen what a CA
was allowed to sign. Name constraints are kept whether critical or not and checked by
`names_permitted`. Chain building and the trust store live in `ca_bundle`.

```otr
import std.crypto.x509
```

## names_permitted

```otr
fn names_permitted(ca: Certificate, ca_der: []u8, c: Certificate, der: []u8, host: ?[]u8) bool
```

Whether the leaf `c` of `der`, and `host` when given, keep to the name constraints of
the CA `ca` of `ca_der` above it (RFC 5280 §4.2.1.10): each SAN entry, and the host the
client asked for. The subject's directory name is not checked, since no host is ever
matched against it here.

## verify_signature

```otr
fn verify_signature(alg: SigAlg, key: PublicKey, key_der: []u8, msg: []u8, sig: []u8) SignatureError!void
```

Checks `sig` over `msg` under the public key `key` of `key_der`, by algorithm `alg`.
TLS's CertificateVerify uses this as well as chain checks.

## matches_host

```otr
fn matches_host(c: Certificate, der: []u8, host: []u8) bool
```

Whether the certificate `c` of `der` names `host`: an IP literal against its SAN
iPAddress entries, anything else against its SAN dNSName entries. The subject's
common name is never consulted (RFC 6125 §6.4.4; the CA/Browser Forum requires the
SAN), so a certificate without one matches no host.
