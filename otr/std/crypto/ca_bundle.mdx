Trust anchors and certificate chain verification. A `Bundle` holds root certificates
as DER, read from PEM files such as the system's CA bundle; adding one records only
where it lies and a hash of its subject, and a root is parsed in full only when a
chain names it as issuer, so loading a few hundred roots costs one base64 pass.

`verify` builds a path from a server's certificate through the intermediates it sent
to a root, checking every signature, validity period, CA flag, path length, key usage,
extended key usage and name constraint on the way, and the host name against the leaf
(RFC 5280 §6 without policy processing; certificates whose critical extensions would
need it are rejected when parsed). `verify_system` does the same against the system's
roots, loaded once per process on first use.

```otr
import std.crypto.ca_bundle
```

### Bundle.add_der

```otr
fn add_der(self: &mut Bundle, der: []u8) asn1.Error!void
```

Adds the DER certificate `der` as a root. Only its outline is checked, as far as
its subject; the rest is parsed when a chain needs it. A certificate already held
is not added twice.

### Bundle.add_pem

```otr
fn add_pem(self: &mut Bundle, text: []u8) usize
```

Adds every `CERTIFICATE` block of the PEM text `text`, returning how many were
added. Blocks that are not valid base64 or not certificates are skipped, as other
TLS stacks skip them, so one bad entry does not cost the rest of a system bundle.

### Bundle.add_file

```otr
fn add_file(self: &mut Bundle, alloc: mem.Allocator, path: str) fs.Error!usize
```

Adds the PEM certificates in the file at `path`.

### Bundle.add_dir

```otr
fn add_dir(self: &mut Bundle, alloc: mem.Allocator, path: str) fs.Error!usize
```

Adds the PEM certificates of every file in the directory `path`, such as
`/etc/ssl/certs`, whose entries are often links to the real files.

### Bundle.load_system

```otr
fn load_system(env: std.Env, alloc: mem.Allocator) LoadError!Bundle
```

The system's roots: `SSL_CERT_FILE` and the directories of `SSL_CERT_DIR`
(separated by `:`) when either is set, as OpenSSL reads them, otherwise the first
of the usual bundle files that holds any certificate.

### Bundle.contains

```otr
fn contains(self: &Bundle, der: []u8) bool
```

Whether `der` is one of the roots.

## verify

```otr
fn verify(b: &Bundle, chain: [][]u8, host: ?[]u8, now: i64) VerifyError!void
```

Verifies `chain`, the server's certificate followed by the intermediates it sent (in
any order, extras ignored), against the roots of `b` at `now` (seconds since the
epoch), and the leaf against `host` when given. Every issuer the chain offers is tried
in turn, backtracking from a path that dead-ends (a cross-signed intermediate whose
first certificate leads to an untrusted or expired root), within `max_signature_checks`.
When no path is found the error says why the last candidate issuer was refused, or is
`UnknownIssuer` (`SelfSigned` for a lone self-signed leaf) when none was named.

## max_signature_checks

```otr
const max_signature_checks: u32 = 64
```

Signature checks one `verify` may spend on candidate issuers, so a chain that offers
many look-alike intermediates costs a bounded time.

## verify_system

```otr
fn verify_system(env: std.Env, chain: [][]u8, host: ?[]u8, now: i64)(LoadError || VerifyError)!void
```

`verify` against the system's roots (`Bundle.load_system`), loading them on first use.
