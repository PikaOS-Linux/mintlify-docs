The running process, the signals it receives, and the programs it starts.

```otr
import std.process
```

## Example

```otr
import std
import std.process

pub fn main(env: std.Env) !void {
    heap := std.mem.heap

    // run_output waits for the child and collects what it wrote.
    out := try process.run_output(heap, &[3]str{ "echo", "hello", "child" })
    defer out.deinit()
    std.io.printf("stdout: {}", .{ out.stdout.as_str() })

    // run passes this process's streams through and reports how the child ended.
    term := try process.run(heap, &[1]str{ "false" })
    switch term {
        .exited |code| => std.io.printf("false exited with {}\n", .{ code })
        .signal |sig| => std.io.printf("false was killed by signal {}\n", .{ sig })
    }

    // spawn starts a child without waiting; wait collects it later.
    child := try process.spawn(heap, &[1]str{ "true" }, .{})
    done := try child.wait(env.io)
    switch done {
        .exited |code| => std.io.printf("true exited with {}\n", .{ code })
        .signal |sig| => std.io.printf("true was killed by signal {}\n", .{ sig })
    }

    if process.run(heap, &[1]str{ "no-such-program-here" }) |_| {} else |err| {
        std.io.printf("missing program: {}\n", .{ err })
    }

    std.io.printf("PATH is set: {}\n", .{ process.get_env("PATH") != null })
}
```

```text
stdout: hello child
false exited with 1
true exited with 0
missing program: error.NotFound
PATH is set: true
```

## run

```otr
fn run(alloc: mem.Allocator, argv: anytype) Error!Term
```

Runs `argv[0]`, looked up in `PATH`, with `argv` as its arguments and this process's
standard streams and environment, and waits for it to end; inside `Io.Uring` only the
calling task waits. `argv` is an array or slice of strings; it may
live in a region, since a region's `[][]r u8` cannot be lent as `[]str` (V1).

## find_executable

```otr
fn find_executable(env: std.Env, name: str, out: []mut u8) ?str
```

The full path of program `name` as `run` and `spawn` would find it: `name` itself
when it contains a `/`, otherwise the first executable `dir/name` for the
directories in `PATH`. The path is written to `out`, which needs room for it and a
NUL byte; null when there is none.

## exec

```otr
fn exec(alloc: mem.Allocator, argv: anytype, options: ExecOptions) Error!noreturn
```

Replaces the running program with `argv[0]`, looked up in `PATH`, with `argv` as its
arguments (execvp(3)), keeping the process id, its descriptors without close-on-exec
and its blocked signals, as a daemon re-executes itself to give memory and threads
back. Pending `defer`s do not run, as for `exit`. Returns only when the program
cannot be started.

## Signals

```otr
const Signals = struct
```

Signals received as values instead of interrupting the program (Linux signalfd).
`init` blocks them on the calling thread, which threads it starts afterwards
inherit; `Io.Threaded` workers block every signal. Create it early in `main`, before
starting threads of your own, so no thread is left to take them the default way.

| Field | Type | Access |
| --- | --- | --- |
| <code>fd</code> | <code>i32</code> | Read-only |
| <code>set</code> | <code>SigSet</code> | Read-only |

## SpawnOptions

```otr
const SpawnOptions = ref struct
```

| Field | Type | Description |
| --- | --- | --- |
| <code>env</code> | <code>?[]str = null</code> | The child's whole environment as `NAME=value` strings; null passes this process's on. |
| <code>cwd</code> | <code>?str = null</code> | The child's working directory; null keeps this process's. |
| <code>cwd_dir</code> | <code>?&amp;linux.Fd = null</code> | The child's working directory as a directory held open, which it enters with fchdir(2) before anything else: unlike a path, a rename or symlink swapped in since cannot redirect it. Takes precedence over `cwd`. |
| <code>detached</code> | <code>bool = false</code> | Starts the child in a session of its own, away from this process's terminal and its signals, and lets it keep running when its `Child` is dropped. |
| <code>setsid</code> | <code>bool = false</code> | Starts the child in a session of its own, as a shell does for a job, but stops it when its `Child` is dropped, unlike `detached`. |
| <code>tty</code> | <code>?str = null</code> | The path of a terminal, such as `Pty.path()` or a virtual console, that the child gets as its standard streams and as its controlling terminal, in a session of its own. |
| <code>fds</code> | <code>?[]FdMap = null</code> | Descriptors the child gets, each at the number given; `.{ child: 1, fd: &p.b }` sends its standard output into a pipe. They take precedence over `tty`. |
| <code>close_others</code> | <code>bool = false</code> | Closes every other descriptor above 2 in the child. Those std opens are close-on-exec anyway; this also covers ones inherited without that flag. |
| <code>nofile</code> | <code>?linux.Rlimit = null</code> | The child's descriptor limit, such as the soft limit this process had before raising its own: programs that `select` break above 1024. Null keeps this process's. |

## Child

```otr
const Child = struct
```

A running program started by `spawn`. Consuming it with `wait` collects how it
ended. `deinit` stops it with SIGKILL and collects it, so a child never outlives
the code that started it by accident, unless it was spawned `detached`; then it
keeps running, and the runtime collects it when it ends.

| Field | Type | Access | Description |
| --- | --- | --- | --- |
| <code>id</code> | <code>i32</code> | Read-only |  |
| <code>fd</code> | <code>i32</code> | Read-only | A pidfd, readable once the child has ended. |
| <code>detached</code> | <code>bool</code> | Read-only |  |

### Child.wait

```otr
fn wait(self: Child, io: std.Io) Error!Term
```

Waits for the child to end; inside `Io.Uring` only the calling task waits. A
cancelled task stops the child as `deinit` does and returns `error.Canceled`.

### Child.kill

```otr
fn kill(self: &Child, sig: Signal) void
```

Sends `sig` to the child.

### Child.pid

```otr
fn pid(self: &Child) i32
```

The child's process id, for calls such as `linux.prlimit`. It names the child only
until it is waited for.

### Child.poll_fd

```otr
fn poll_fd(self: &Child) i32
```

Ready once the child has ended, for `Io.select`.

### Child.deinit

```otr
fn deinit(self: Child) void
```

## spawn

```otr
fn spawn(alloc: mem.Allocator, argv: anytype, options: SpawnOptions) Error!Child
```

Starts `argv[0]`, looked up in `PATH`, with `argv` as its arguments and this
process's standard streams, without waiting for it. `argv` is an array or slice of
strings, as for `run`. Signals blocked here, as by `Signals`, are not blocked in the
child.
