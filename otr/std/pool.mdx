Generational handles (spec §7.7): a `Handle` names a slot and the generation it was
issued for, so a handle to a removed value reads as `null` instead of dangling.

```otr
import std.pool
```

## Example

```otr
import std
import std.pool

const Window = struct {
    title: []static u8
    width: i64
}

pub fn main() void {
    var windows = pool.Pool(Window).init(std.mem.heap)
    defer windows.deinit()

    // A handle is a small copyable value that can be stored anywhere.
    term := windows.insert(.{ title: "term", width: 640 })
    files := windows.insert(.{ title: "files", width: 800 })

    if windows.get_mut(term) |w| {
        w.width = 1024
    }
    _ = windows.update(files, fn(w: &mut Window) void { w.width += 100 })
    std.io.printf("{} {}\n", .{ windows.at(term).title, windows.at(term).width })
    std.io.printf("{} {}\n", .{ windows.at(files).title, windows.at(files).width })

    if windows.remove(term) |gone| {
        std.io.printf("closed {}\n", .{ gone.title })
    }

    // The slot is reused, but the old handle no longer matches its generation.
    editor := windows.insert(.{ title: "editor", width: 900 })
    std.io.printf("stale handle: {}\n", .{ windows.get(term) == null })
    if windows.get(editor) |w| {
        std.io.printf("new window: {}\n", .{ w.title })
    }
}
```

```text
term 1024
files 900
closed term
stale handle: true
new window: editor
```

## Pool

```otr
fn Pool(comptime T: type) type
```

Values that own resources are kept apart from their slots, so they move in and out of
a freed slot whole; other values sit in their slots, beside the generation that guards
them, which `get` then reads from one cache line (`bench/pool`).

A slot's generation counts its lives and its parity says whether it holds a value: odd
while live, even while free, so `get` compares one field and there is no live flag.
Handles carry odd generations. A slot whose live generation reaches the limit (2^32 - 1,
after 2^31 lives) is retired instead of reused, so a stale handle can never match a later
value (ABA); the pool only grows by that slot.

| Field | Type | Access |
| --- | --- | --- |
| <code>slots</code> | <code>mem.RawBuf(Slot)</code> | Read-only |
| <code>len</code> | <code>u32</code> | Read-only |
| <code>cap</code> | <code>u32</code> | Read-only |
| <code>free</code> | <code>list.List(u32)</code> | Read-only |
| <code>alloc</code> | <code>mem.Allocator</code> | Read-only |

## SoaPool

```otr
fn SoaPool(comptime T: type) type
```

`Pool` with each field of the slots, and of the struct `T`, in its own column
(spec D1). A `soa` element is not contiguous, so it has no address: `get` and `at`
return copies, and `set` and `update` write a value back. There is no `get_mut`.

| Field | Type | Access |
| --- | --- | --- |
| <code>base</code> | <code>?[*]u8</code> | Read-only |
| <code>len</code> | <code>u32</code> | Read-only |
| <code>cap</code> | <code>u32</code> | Read-only |
| <code>free</code> | <code>list.List(u32)</code> | Read-only |
| <code>alloc</code> | <code>mem.Allocator</code> | Read-only |

## Link


## Chain

```otr
fn Chain(comptime T: type, comptime field: []static u8) type
```

A doubly linked list of a pool's elements through their `Link` field `field`, as C and
Zig link objects through a member and find the object again with `container_of`: O(1)
insertion and removal, no allocation, and an element may be in one chain per `Link`
field. Elements are named by handle, so one removed from the pool while still linked
ends the chain there instead of being reached.

| Field | Type | Access |
| --- | --- | --- |
| <code>head</code> | <code>?H</code> | Read-only |
| <code>tail</code> | <code>?H</code> | Read-only |
| <code>len</code> | <code>usize</code> | Read-only |

### Chain.init
