## Install the package

On PikaOS, install the `otr` package:

```bash
pikman install otr
```

The package puts the whole toolchain under `/usr/lib/otr` and links `/usr/bin/otr` to its compiler. It is about 580 MB installed, because it carries its own clang, linker and C libraries.

Check the version:

```bash
otr version
```

```text
otr 0.2.6
```

## What gets installed

| Path under `/usr/lib/otr` | Contents |
| --- | --- |
| `bin/otr` | The compiler, formatter, test runner, documentation tool and language server |
| `lib/libotr-tpde.so` | The TPDE backend used for debug builds |
| `lib/otr/llvm` | clang 23.1.3, libclang, and the linker plugin used for release builds |
| `lib/otr/libc` | Headers and libraries for `x86_64-linux-gnu`, `x86_64-linux-musl`, `aarch64-linux-gnu` and `aarch64-linux-musl`, plus compiler-rt |
| `libexec/otr/mold` | The mold linker |

You do not need gcc, a system clang, or libc development headers to build an otr program. You do need the development headers of any other C library you import, such as `libwayland-dev` for `wayland-client.h`.

## System requirements

The toolchain runs on x86-64 Linux with glibc 2.38 or newer.

Programs you build with it have looser requirements. A glibc build links against stub libraries that hold only the symbols of glibc 2.34 and older, so it runs on any glibc from 2.34. A musl build is static and runs on any Linux of its architecture.

## Build from source

You need an installed otr to build otr. `tools/bootstrap.sh` downloads the release that the checkout pins, checks it against its checksum, and prints the path of its compiler.

Install the tools that the build downloads and unpacks with: `curl`, `tar`, `dpkg-deb`, and python3 3.9 or newer.

```bash
git clone https://git.pika-os.com/general-packages/otr.git
cd otr

otr=$(sh tools/bootstrap.sh)
"$otr" run build.otr -- install --boot "$otr"
```

This writes a complete toolchain to `out/`, with the compiler at `out/bin/otr`. The build compiles stage 1 with the bootstrap compiler, then stage 1 compiles the compiler that gets installed. Each download is pinned by checksum and kept in `~/.cache/otr`.

Later rebuilds use the installed compiler:

```bash
out/bin/otr run build.otr -- install
```

The build runner has more steps:

| Step | What it does |
| --- | --- |
| `install [--out DIR] [--boot OTR]` | Builds a complete toolchain into `DIR` (default `out`) |
| `test [--jobs N] [--update-snapshots]` | Runs every test suite against the installed compiler, including the reproducibility check |
| `cross-test --qemu QEMU [--sysroot DIR]` | Runs the behaviour and C ABI suites for AArch64 under qemu-user |
| `fuzz-safety [--iterations N] [--seed S]` | Fuzzes the borrow checker against the reference checker |
| `proofs [--lake LAKE]` | Checks the Lean proofs of the safety rules |
| `dist` | Packs the toolchain into `otr-<arch>-linux.tar.xz` |

<Note>The bootstrap script only knows a release for x86-64. On another architecture it stops with `no otr release for <arch> yet`.</Note>

## Editor support

`otr lsp` runs a language server on stdin and stdout. Point any editor that speaks the Language Server Protocol at that command for `.otr` files. The server reads the `otr.toml` above each open document, so a module of a dependency is checked as part of its own package.

`otr fmt <file>...` formats files in place. Run it on save, or use `otr fmt --check` in CI to report unformatted files without changing them.
