# otter-conf

A high-performance, comptime-generic configuration library for Zig.

otter-conf parses simple key-value configuration files into Zig structs at runtime, using comptime reflection to generate specialized parsers with zero runtime overhead. Files are loaded via memory-mapped I/O for optimal performance.

## Features

- **Faster than std.json** - ~28% faster with 60% fewer instructions (see benchmarks)
- **Comptime-generic parsing** - Define your config as a Zig struct, get a specialized parser for free
- **SIMD-optimized** - Vectorized string scanning and comment skipping via `std.mem.indexOfScalar`
- **Memory-mapped I/O** - Efficient file loading with minimal syscall overhead
- **Zero-copy where possible** - Strings reference the mapped memory when safe
- **Full type support** - Booleans, integers (all sizes), floats, strings, enums, arrays, slices, optionals, nested structs, and custom value types
- **Forward-compatible parsing** - Unknown fields are silently skipped, enabling seamless config schema evolution
- **Serialization** - Write configs back to files with proper formatting
- **Directory loading** - Load multiple config files with override support
- **Hot-reload detection** - Check if files have changed since loading
- **File watching** - inotify-based watcher for real-time config hot-reload

## Installation

Add otter-conf to your `build.zig.zon`:

```bash
zig fetch --save git+https://github.com/user/otter-conf
```

Then in your `build.zig`:

```zig
const otter_conf = b.dependency("otter_conf", .{
    .target = target,
    .optimize = optimize,
});
exe.root_module.addImport("otter_conf", otter_conf.module("otter_conf"));
```

## Quick Start

```zig
const std = @import("std");
const otter = @import("otter_conf");

const Config = struct {
    name: []const u8 = "default",
    port: u16 = 8080,
    debug: bool = false,
    timeout: f64 = 30.0,
    log_level: enum { Debug, Info, Warn, Error } = .Info,
};

pub fn main() !void {
    var gpa = std.heap.GeneralPurposeAllocator(.{}){};
    defer _ = gpa.deinit();
    const allocator = gpa.allocator();

    // Load from file
    var config = try otter.load(Config, allocator, "/etc/myapp/config.conf", .{});
    defer otter.freeConfig(Config, allocator, &config);

    std.debug.print("Server: {s}:{d}\n", .{ config.name, config.port });
}
```

Configuration file (`/etc/myapp/config.conf`):
```
# Application configuration
name = "production-server"
port = 443
debug = false
timeout = 60.5
log_level = Warn
```

## Configuration Format

otter-conf uses a simple, flat key-value format optimized for readability and parsing speed.

### Basic Syntax

```
# Comments start with hash
key = value
```

- Keys are identifiers (alphanumeric plus underscores)
- Values are separated from keys by `=`
- Whitespace around `=` is ignored
- Lines starting with `#` are comments
- Empty lines are ignored

### Supported Types

#### Booleans
```
enabled = true
disabled = false
```

#### Integers
All Zig integer types are supported: `i8`, `i16`, `i32`, `i64`, `u8`, `u16`, `u32`, `u64`, etc.
```
port = 8080
max_connections = 1000
negative = -42
large_unsigned = 18446744073709551615
```

#### Floats
Both `f32` and `f64` are supported.
```
rate = 3.14159
temperature = -40.5
scale = 1.0
```

#### Strings
Strings are enclosed in double quotes. Escape sequences are supported.
```
name = "my-application"
path = "/home/user/config"
message = "Hello \"World\"\nNew line here"
```

Supported escape sequences:
- `\"` - Double quote
- `\\` - Backslash
- `\n` - Newline
- `\r` - Carriage return
- `\t` - Tab

#### Enums
Enum values are written without quotes, matching the Zig field name exactly.
```
log_level = Debug
mode = Production
scheduler = bpfland
```

#### Arrays (Fixed Size)
Fixed-size arrays use bracket notation.
```
rgb = [255, 128, 0]
coordinates = [1.5, 2.5, 3.5]
flags = [true, false, true]
```

#### Slices (Dynamic)
Slices are parsed the same as arrays but allocated on the heap.
```
ports = [80, 443, 8080]
hosts = ["localhost", "127.0.0.1", "example.com"]
```

#### Optionals
Optional fields use the same syntax as their inner type. If not specified in the config file, they retain their default value (typically `null`).
```
# In struct: fps_limit: ?i64 = null
fps_limit = 144

# In struct: custom_path: ?[]const u8 = null
custom_path = "/custom/path"
```

### Complete Example

```
# Server Configuration
# Generated by otter-conf

name = "api-gateway"
version = "2.1.0"

# Network settings
host = "0.0.0.0"
port = 8443
max_connections = 10000

# Timeouts (in seconds)
read_timeout = 30.0
write_timeout = 60.0

# Feature flags
debug = false
metrics_enabled = true
compression = true

# Logging
log_level = Info
log_format = JSON

# TLS configuration
tls_cert = "/etc/ssl/server.crt"
tls_key = "/etc/ssl/server.key"

# Allowed origins for CORS
allowed_origins = ["https://example.com", "https://app.example.com"]

# Rate limiting (requests per second)
rate_limits = [100, 500, 1000]
```

## API Reference

### Loading Functions

#### `load`
```zig
pub fn load(
    comptime T: type,
    allocator: std.mem.Allocator,
    path: []const u8,
    options: LoadOptions,
) LoadError!T
```
Load and parse a configuration file. The path must be absolute.

#### `loadWithMetadata`
```zig
pub fn loadWithMetadata(
    comptime T: type,
    allocator: std.mem.Allocator,
    path: []const u8,
    options: LoadOptions,
) LoadError!LoadResult(T)
```
Load a configuration file and return metadata including file size and modification time. Useful for implementing hot-reload.

```zig
const result = try otter.loadWithMetadata(Config, allocator, path, .{});
var config = result.config;
defer otter.freeConfig(Config, allocator, &config);

std.debug.print("Loaded {d} bytes, mtime: {d}\n", .{ result.file_size, result.mtime_ns });
```

#### `loadFromSlice`
```zig
pub fn loadFromSlice(
    comptime T: type,
    allocator: std.mem.Allocator,
    content: []const u8,
) ParseError!T
```
Parse configuration from a byte slice. Useful for embedded configs or testing.

```zig
const content = @embedFile("default.conf");
const config = try otter.loadFromSlice(Config, allocator, content);
```

#### `loadOrCreate`
```zig
pub fn loadOrCreate(
    comptime T: type,
    allocator: std.mem.Allocator,
    path: []const u8,
    load_options: LoadOptions,
    save_options: SerializeOptions,
) !T
```
Load a config file, or create it with default values if it doesn't exist. Otter-matically handles first-run scenarios.

### Directory Loading

#### `loadDir`
```zig
pub fn loadDir(
    comptime T: type,
    allocator: std.mem.Allocator,
    dir_path: []const u8,
    options: DirLoadOptions,
) DirLoadError!DirLoadResult(T)
```
Load all configuration files from a directory.

```zig
const profiles = try otter.loadDir(GameProfile, allocator, "/etc/game/profiles.d", .{
    .extension = ".conf",
    .recursive = false,
});
defer profiles.deinit(true);

for (profiles.entries) |entry| {
    std.debug.print("Profile: {s} from {s}\n", .{ entry.config.name, entry.filename });
}
```

#### `loadWithOverrides`
```zig
pub fn loadWithOverrides(
    comptime T: type,
    allocator: std.mem.Allocator,
    base_dir: []const u8,
    override_dir: ?[]const u8,
    options: DirLoadOptions,
) DirLoadError!DirLoadResult(T)
```
Load configs from a base directory with user overrides. Files in the override directory replace files with matching names from the base directory.

```zig
// System configs in /etc/app/conf.d/
// User overrides in ~/.config/app/conf.d/
const configs = try otter.loadWithOverrides(
    Config,
    allocator,
    "/etc/app/conf.d",
    home_config_path,
    .{},
);
```

### Hot-Reload Support

#### `hasChanged`
```zig
pub fn hasChanged(path: []const u8, last_mtime_ns: i128) !bool
```
Check if a file has been modified since the given modification time.

```zig
// Store mtime when loading
const result = try otter.loadWithMetadata(Config, allocator, path, .{});
const last_mtime = result.mtime_ns;

// Later, check for changes
if (try otter.hasChanged(path, last_mtime)) {
    // Reload configuration
}
```

#### `getMtime`
```zig
pub fn getMtime(path: []const u8) !i128
```
Get the current modification time of a file.

### File Watcher

For real-time hot-reload, otter-conf provides an inotify-based file watcher that integrates with your application's event loop.

#### `Watcher`
```zig
const otter = @import("otter_conf");

// Initialize watcher
var watcher = try otter.Watcher.init(allocator);
defer watcher.deinit();

// Add a file to watch
const wd = try watcher.addWatch(allocator, "/path/to/config.conf");

// In your event loop, poll the watcher fd
const watcher_fd = watcher.getFd();

// When fd is readable, process events
while (watcher.nextEvent()) |event| {
    if (event.isModified()) {
        // Config file was modified - reload it
        config = try otter.load(Config, allocator, path, .{});
    }
}
```

#### Watcher Methods

- `init(allocator)` - Create a new watcher instance
- `deinit()` - Clean up watcher and all watches
- `addWatch(allocator, path)` - Add a file to watch, returns watch descriptor
- `removeWatch(wd)` - Remove a watch by descriptor
- `getFd()` - Get the inotify file descriptor for polling
- `getPath(wd)` - Get the path associated with a watch descriptor
- `nextEvent()` - Get the next pending event (call after fd is readable)
- `hasPendingEvents()` - Non-blocking check for pending events

#### WatchEvent Methods

- `isModified()` - File was written to and closed (IN_CLOSE_WRITE)
- `isDeleted()` - File was deleted
- `isCreated()` - File was created
- `isMoved()` - File was moved or renamed
- `isIgnored()` - Watch was removed (file deleted or unmounted)

#### Integration Example

```zig
// Poll both wayland and config watcher
var fds = [_]std.posix.pollfd{
    .{ .fd = wayland_fd, .events = std.posix.POLL.IN, .revents = 0 },
    .{ .fd = watcher.getFd(), .events = std.posix.POLL.IN, .revents = 0 },
};

_ = std.posix.poll(&fds, -1);

if (fds[1].revents & std.posix.POLL.IN != 0) {
    while (watcher.nextEvent()) |event| {
        if (event.isModified()) {
            // Reload configuration
        }
    }
}
```

## Defining Config Structs

Config structs must have default values for all fields. This enables partial configs where only changed values need to be specified.

```zig
const ServerConfig = struct {
    // Strings - default to empty or sensible value
    name: []const u8 = "unnamed",
    host: []const u8 = "127.0.0.1",

    // Integers - any size
    port: u16 = 8080,
    max_connections: u32 = 1000,

    // Floats
    timeout_seconds: f64 = 30.0,

    // Booleans
    debug: bool = false,

    // Enums - define inline or separately
    log_level: enum { Debug, Info, Warn, Error } = .Info,

    // Optionals - for truly optional values
    tls_cert: ?[]const u8 = null,
    tls_key: ?[]const u8 = null,

    // Fixed arrays
    retry_delays: [3]u32 = .{ 1, 5, 30 },

    // Dynamic slices - default to empty
    allowed_ips: []const []const u8 = &[_][]const u8{},
    ports: []const i64 = &[_]i64{},
};
```

## Performance

otter-conf is designed for speed. The parser uses range-based switch statements (like std.json), SIMD-optimized string scanning, and comptime code generation to eliminate runtime type checking.

### Benchmarks vs std.json and TOML

Measured on AMD Ryzen 9 9950X3D (native compilation, ReleaseFast, 1000 iterations):

| Size | otter-conf | std.json | zig-toml |
|------|------------|----------|----------|
| Small | **2.83ms** | 4.03ms (+42%) | 9.78ms (+246%) |
| Medium | **10.7ms** | 13.0ms (+22%) | 16.1ms (+51%) |
| Large | **29.3ms** | 35.3ms (+21%) | 44.3ms (+51%) |

**Average: ~28% faster than std.json, ~116% faster than zig-toml**

```
Benchmark: Large config (~12KB), 1000 iterations

./zig-out/bin/bench-otter large 1000
  wall_time    29.3ms    instructions  262M    branch_misses  163K

./zig-out/bin/bench-json large 1000
  wall_time    35.3ms    instructions  679M    branch_misses  337K    +21% slower

./zig-out/bin/bench-toml large 1000
  wall_time    44.3ms    instructions  664M    branch_misses  554K    +51% slower
```

otter-conf achieves this by:
- **60% fewer instructions** than both JSON and TOML parsers
- **50-65% fewer branch misses** through predictable parsing patterns
- **Range-based switches** that compile to efficient jump tables
- **SIMD memchr** for fast string and comment scanning

### Why So Fast?

1. **Comptime specialization** - The parser is generated at compile time for your specific struct, eliminating all runtime type dispatch
2. **Range-based switches** - Character classification uses `'0'...'9'` ranges that compile to efficient jump tables (same technique as std.json)
3. **SIMD string scanning** - Uses `std.mem.indexOfScalar` (vectorized memchr) to find string terminators and newlines
4. **Minimal allocations** - Strings are copied once, no intermediate buffers
5. **Memory-mapped I/O** - Single syscall to map files, lazy page loading, zero-copy where possible

## Thread Safety

otter-conf parsers are not thread-safe for concurrent parsing of the same content. However:
- Multiple threads can safely parse different files
- Loaded configs (the resulting structs) can be shared between threads if not modified
- For concurrent access to the same config file, load once and share the result

## Nested Structs

otter-conf supports nested structs with automatic key flattening. Sub-struct fields are accessed via `prefix_field` in the config file:

```zig
const ClockConfig = struct {
    enabled: bool = true,
    text_color: Color = Color.white,
};

const Config = struct {
    clock: ClockConfig = .{},
    name: []const u8 = "default",
};
```

```
# Config file
clock_enabled = true
clock_text_color = "#FF0000FF"
name = "my-app"
```

Direct field matches take priority over nested prefix matches. Nested structs are detected at comptime — a struct field is treated as a container if it has no `parse` method and has at least one field.

## Custom Value Types

Structs that implement `parse` and `toStr` are treated as custom value types rather than containers. The parser reads them as strings and calls `parse()`:

```zig
const Color = packed struct(u32) {
    // ...
    pub fn parse(str: []const u8) !Color { ... }
    pub fn toStr(self: Color) [9]u8 { ... }
};

const Config = struct {
    background: Color = Color.white,
};
```

```
background = "#FFFFFFFF"
```

If `parse()` returns an error, the field keeps its default value.

## Dynamic fields

Use `Dynamic(T, prefix)` to model indexed collections of entries addressed by a
numeric index or a shared prefix:

```zig
const Bind = struct {
    mods: u32 = 0,
    key: []const u8 = "",
    action: []const u8 = "",
};

const Config = struct {
    binds: otter_conf.Dynamic(Bind, "bind") = .{},
};
```

The parser absorbs any of:

```text
bind = "Super+q,killclient"          # bare form, requires T.parse
bind_0 = "Super+Return,spawn,kitty"  # indexed bare form, requires T.parse
bind_1_mods = 4                      # indexed struct-field form
bind_1_key = "q"
bind_1_action = "killclient"
```

Entries are stored in declaration order in `config.binds.items`. Indexed forms
accept indices `0..4095`; larger sparse indices return `error.ArrayTooLarge`.
Ownership: a per-Dynamic arena backs the slice and any strings inside it. Call
`config.binds.deinit(gpa)` when done.

## Imports

Split a config across files:

```text
# ~/.config/app/config.conf
import = "binds.conf"
import = "rules.conf"
name = "main"
```

Use `loadWithImports`:

```zig
var res = try otter_conf.loadWithImports(Config, gpa, path, .{});
defer res.deinit(gpa);
// res.config  — parsed Config
// res.paths   — absolute paths of every file loaded (for watcher)
```

Semantics:
- Relative paths resolve against the parent file's directory.
- Typed fields: last write wins (main file overrides imports).
- `Dynamic` fields: append in load order (imports first, main last).
- Circular imports return `error.CircularImport`.
- Import nesting is capped at 128 files deep.
- Merged import output is capped by `LoadOptions.max_file_size`.

## Limitations

- **No inline comments** - Comments must be on their own line
- **ASCII only** - Field names must be ASCII identifiers
- **No multiline strings** - Use `\n` escape sequences instead
- **Single-level nesting** - Nested structs support one level of nesting (no deeply nested paths)
